# Web-to-native parity map — 9 November 2026

This is the current **0.8.1 source checkpoint**: journal/settings and account parity, optional moods/priorities, reviewed note intake, monthly recap and Android push are implemented. Earlier map entries retain their narrower evidence; exact current APK/AAB hashes and real Redmi/emulator checks belong in VERIFICATION.md. Nudge is an independent React Native + Expo Android app with embedded code/assets and shared Supabase accounts/backend. It requires neither Expo Go nor Metro to run and has not been published to Google Play. Keep the Nudge name, shared mark and blue identity.

The owner's latest direction governs the UI: a signed-out person begins with six short questions, not an entry/sign-in screen; food and humor come first. Tapping an option, neutral response or Skip saves locally and advances. Back revisits an answer. Sign-in appears only after all six responses. Today uses the same direct tap-to-save rhythm; ranking and writing retain an explicit Save because they require multiple edits. The app is **light-only**. Five native destinations remain: **Today, You, Decide, Tools, Account**. Secondary actions belong in compact menus or their relevant detail screen, not a wall of introductory text or plain blue links.

## Backend and concurrency boundary

The deployed account/settings/foundation/tools adapters join the existing discovery/decision/journal/choice/reflection/reminder APIs. Native bearer identity is verified with Supabase; invalid bearer credentials never fall back to browser cookies. The APK packages public endpoint configuration, not service-role or AI secrets. The Next web build excludes `mobile/` so native code/dependencies do not leak into web compilation.

Authoritative writes do not retry automatically. Discovery changes retain exact request ID/body/generation/revision for explicit recovery; a conflict requires new review, not a silently rebased intent. A successful server write followed by failed refresh is shown as saved with refresh required. Circle/poll creation has different deduplication limits and reloads after uncertainty. Account changes must clear account-bound UI and device drafts; sign-in does not implicitly claim a preview.

Real HTTPS 0.4 report: `.local/mobile-0.4-hosted-parity.json`, all recorded checks true, no error, cleanup **2 created / 2 deleted and absence verified**. It covers combined category/owner filtering, abandonment replay/isolation and saved-choice protection, custom-time/reminder isolation, bounded activity/preference timeline isolation and invalid-bearer rejection. The earlier broad account/settings/comparison/learning/circle checks remain in `.local/mobile-0.3-hosted-parity.json`. These reports explicitly exclude Google UI, installed-app and push proof.

Earlier installed correction reports remain versioned: `.local/mobile-0.3-back-device-proof.json` records unchanged answer count, changed existing answer, advanced revision/privacy generation; `.local/mobile-0.3-device-retry.json` records tap-save/advance, Back reopen, visible offline correction failure and successful explicit retry. Those results belong to their recorded 0.3 hashes, not automatically to 0.4. Current installed-build pairings and 0.4 device evidence belong in VERIFICATION. Screenshots in `mobile/design/evidence/` are actual Android captures when identified as such; phase specification boards are proposals, not screenshots.
