## Hosted scheduler

`supabase/native_push_scheduler.sql` is optional original-project administration, separate from portable migrations. It reads `nudge_native_push_cron` from Vault at dispatch time and calls the fixed Nudge endpoint every five minutes. Its function is unavailable to public/anonymous/authenticated/service roles. No secret literal belongs in saved SQL. A restored database/branch must disable this production-calling job before use. `pg_net` briefly holds the header in its internal request queue; database administrators can access it. See [Supabase scheduling](https://supabase.com/docs/guides/functions/schedule-functions).

Owner explicitly approved the Vault transmission, pg_net installation and schedule. Installed and observed: `nudge-native-push`, `*/5 * * * *`, active=true; scheduler function private=true. A real Supabase pg_net dispatch returned HTTP200, timed_out=false, worker_ok=true. Capture `mobile/design/evidence/native-push-scheduler-verified.png`. This proves the scheduler-to-backend path, not device delivery.
