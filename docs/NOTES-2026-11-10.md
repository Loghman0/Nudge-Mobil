# Native reviewed notes — 0.6.0 checkpoint

Implemented Tools → Add a note using existing components/tokens. A note (3–2,000 characters) is submitted explicitly; suggestions start unselected. Users edit statement/type, move between at most six suggestions, select entries and explicitly confirm review. Nothing is written during extraction. Text/review stay in component memory, not a new local note cache. Successful saving clears them; leaving the screen discards this local state.

Saving pins an independent request UUID/body/privacy generation. An uncertain response freezes edits and offers **Check same save request**; it does not generate another save identity. A generation/consent conflict discards obsolete suggestions and requires fresh review. Closing an uncertain review tells the user to inspect Memory library. Navigation within Tools is locked while a request is in flight. Account-keyed Tools instances and unmount guards prevent stale results from updating a later account's review.

Backend `POST /api/v1/tools/memories/extract` and `/confirm` reuse `extractProfileMemories`, `getAccountedAi(..., 'extract')` and `confirmProfileMemoryReview`. Identity comes from the existing verified native bearer/browser-origin authenticator. Current terms, explicit AI consent, durable attempt/usage accounting and the database's idempotent reviewed-save RPC remain authoritative. No new database migration, provider selection, automatic memory save or mobile AI secret was added.
